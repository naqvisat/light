AWS Storage - Instance Store, EBS, EFS & FSx - Complete SAA-C03 Cheat Sheet

A simple text reader version of the storage cheat sheet covering Instance Store, EBS, EFS, FSx, hybrid storage, backups, and migration patterns.

1. Storage Types Overview

  • AWS offers four main categories of storage attached to or accessible from EC2 instances.
  • Instance Store: Ephemeral, physically attached block storage. Highest performance. Data lost on stop or terminate.
  • EBS (Elastic Block Store): Persistent, network-attached block storage. One instance per volume by default. AZ-specific.
  • EFS (Elastic File System): Managed NFS file system. Shared across many instances. Multi-AZ. Linux only.
  • FSx: Managed third-party file systems for Windows, Lustre, NetApp ONTAP, and OpenZFS workloads.
  • Block storage: Instance Store and EBS. File storage: EFS and FSx.

2. EC2 Instance Store - Deep Dive

  • Physically attached NVMe SSD or HDD disks on the host server, included with certain instance types.
  • Performance: Highest possible IOPS of any EC2 storage option, often millions of IOPS.
  • Ephemeral: Data is lost when the instance is stopped, terminated, or the host hardware fails. Data survives reboot.
  • Cannot be detached, resized, or natively snapshotted. You must manually copy data elsewhere for backup.
  • Size, type, and count are determined by the instance type.
  • Best for buffer, cache, scratch data, swap space, and transient high-IOPS workloads.

3. EBS (Elastic Block Store) - Fundamentals

  • Network-attached block storage that behaves like a virtual hard drive.
  • Persistence: Data survives stop and restart, and can survive termination if Delete on Termination is disabled.
  • AZ-specific: A volume exists in one AZ and can only attach to instances in that same AZ.
  • One-to-one attachment: One volume to one instance by default, except Multi-Attach for io1 and io2.
  • Volumes can be detached and attached to another instance in the same AZ without data loss.
  • Encryption: AES-256 with KMS for data at rest and in transit.

4. EBS Volume Types - SSD

  • gp3: Default SSD choice with independent scaling for IOPS and throughput.
  • gp2: Older general-purpose SSD where IOPS scales with size.
  • io2 Block Express: Highest-performance EBS volume, up to 256,000 IOPS and 4,000 MB/s throughput.
  • io2: Provisioned IOPS SSD up to 64,000 IOPS with 99.999 percent durability.
  • io1: Older provisioned IOPS generation being replaced by io2.

5. EBS Volume Types - HDD

  • st1: Throughput Optimized HDD for sequential workloads like big data and log processing. Cannot be a boot volume.
  • sc1: Cold HDD for the cheapest infrequently accessed storage. Cannot be a boot volume.
  • HDD exam rule: If the question says boot volume, eliminate st1 and sc1.

6. EBS Multi-Attach

  • Attach one io1 or io2 volume to up to 16 Nitro-based instances in the same AZ.
  • All instances can read and write concurrently.
  • The application must manage concurrent writes using a cluster-aware file system or coordination layer.
  • Use for clustered applications that need shared block storage in one AZ.

7. EBS Snapshots - Deep Dive

  • Point-in-time EBS backups stored in S3 and managed by AWS. Incremental after the first snapshot.
  • Snapshots are Region-specific but can be copied cross-Region or shared cross-account.
  • To move a volume, snapshot it and create a new volume in the target AZ or Region.
  • Snapshot lifecycle automation: Use Amazon Data Lifecycle Manager (DLM).
  • EBS Snapshot Archive: Cheaper long-term tier with 24 to 72 hour retrieval.
  • Recycle Bin: Protects snapshots from accidental deletion.
  • Fast Snapshot Restore: Pre-warms volumes created from snapshots for immediate full performance.

8. EBS RAID Configurations

  • RAID 0: Striping for higher performance. No redundancy.
  • RAID 1: Mirroring for redundancy at the cost of usable capacity.
  • RAID 5 and RAID 6: Not recommended by AWS for EBS due to parity overhead.
  • Exam pattern: more than 64,000 IOPS may mean RAID 0 with multiple io2 volumes or io2 Block Express.

10. EFS (Elastic File System) - Fundamentals

  • Managed, serverless NFS file system with pay-per-use pricing.
  • Multi-AZ by default: Can be mounted by many instances across AZs simultaneously.
  • Linux only. For Windows shared storage, use FSx for Windows File Server.
  • Use for CMS, web serving, home directories, analytics, containers, and ML training data.
  • Compatible with EC2, ECS, EKS, Fargate, Lambda, and on-premises over DX or VPN.
  • Security includes KMS encryption, TLS in transit, POSIX permissions, security groups, IAM, and Access Points.

11. EFS Performance

  • Performance Modes: General Purpose for low latency and Max I/O for very large parallel workloads.
  • Throughput Modes: Bursting, Elastic, and Provisioned.
  • Exam pattern: Small file system but high throughput requirement means Elastic or Provisioned throughput mode.

12. EFS Storage Classes & Lifecycle

  • Standard: Frequently accessed, multi-AZ storage.
  • Infrequent Access (IA): Lower storage cost with small access charges.
  • One Zone: Single-AZ storage with lower cost and lower durability.
  • Archive: Lowest-cost tier for very rarely accessed data.
  • EFS Lifecycle Management: Automatically moves files between tiers and can transition them back on access.

13. EFS Access Points

  • Application-specific entry points into an EFS file system.
  • Each access point enforces a POSIX identity, root directory, and permissions.
  • Useful for multi-tenant environments and least-privilege application access.

15. Amazon FSx - Overview

  • FSx provides fully managed third-party file systems optimized for specific workloads.
  • Variants: FSx for Windows File Server, FSx for Lustre, FSx for NetApp ONTAP, and FSx for OpenZFS.
  • Key differentiator from EFS: FSx supports Windows, HPC-specific systems, and advanced enterprise storage features.

16. FSx for Windows File Server

  • Fully managed Windows-native file system built on Windows Server.
  • Protocol: SMB, plus optional NFS access.
  • Active Directory integration: Supports AWS Managed Microsoft AD or self-managed AD.
  • Features include DFS, shadow copies, deduplication, and automatic daily backups.
  • Multi-AZ option provides active/standby high availability with automatic failover.
  • Best for Windows shared storage and AD-integrated file share migrations.

17. FSx for Lustre

  • High-performance parallel file system for compute-intensive workloads.
  • Best for machine learning training, HPC, financial modeling, rendering, genomics, and similar workloads.
  • Native S3 integration: Link an S3 bucket and lazily load data on first access, with optional sync back to S3.
  • Scratch: Temporary highest-performance deployment with no replication.
  • Persistent: Long-term deployment with replicated data and failover.

18. FSx for NetApp ONTAP

  • Feature-rich managed NetApp ONTAP file system supporting NFS, SMB, and iSCSI simultaneously.
  • Features include snapshots, FlexClone, compression, deduplication, replication, and data tiering.
  • Supports multi-AZ deployment with automatic failover.
  • Best for multi-protocol access, NetApp migrations, and instant zero-space clones for dev and test.

19. FSx for OpenZFS

  • Managed file system built on OpenZFS for Linux and macOS workloads.
  • Protocol: NFS only.
  • Supports snapshots, cloning, and automatic compression.
  • No SMB, no iSCSI, and no multi-AZ deployment.
  • Best for ZFS migrations and high-IOPS NFS workloads.

21. AWS Backup

  • Centralized backup service across EBS, EFS, FSx, RDS, DynamoDB, Aurora, S3, and more.
  • Backup Plans: Define schedules, retention, cold storage transitions, and cross-Region copy rules.
  • Backup Vault: Stores backups and can use Vault Lock for immutable WORM compliance.
  • Supports cross-Region and cross-account copy for DR and isolation.

22. AWS Storage Gateway - Hybrid Storage

  • Bridges on-premises infrastructure with AWS storage.
  • S3 File Gateway: On-premises NFS or SMB share backed by S3.
  • FSx File Gateway: Local cache for FSx for Windows File Server shares.
  • Volume Gateway: iSCSI block storage backed by S3 in Cached or Stored mode.
  • Tape Gateway: Virtual tape library backed by S3 and Glacier.

23. AWS DataSync

  • Managed data transfer service for moving data between on-premises and AWS, or between AWS services.
  • Supports NFS, SMB, HDFS, object storage, S3, EFS, and all FSx variants.
  • Features include encryption, integrity validation, scheduling, filtering, and bandwidth throttling.
  • DataSync vs Storage Gateway: DataSync moves data. Storage Gateway provides ongoing hybrid access.

24. AWS Snow Family

  • Physical devices for offline data transfer and edge computing.
  • Snowcone: Smallest device for portable and rugged use cases.
  • Snowball Edge Storage Optimized: Best for large-scale migration and local storage.
  • Snowball Edge Compute Optimized: Best for edge ML inference and disconnected compute.
  • Snowmobile: Up to 100 PB per truck for exabyte-scale migrations.
  • Rule of thumb: If network transfer takes more than a week, use Snow Family.

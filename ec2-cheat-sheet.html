AWS EC2 - Complete SAA-C03 Cheat Sheet

A simple text reader version of the full EC2 cheat sheet, preserving the original section structure and decision matrix.

1. EC2 Fundamentals

  • EC2 (Elastic Compute Cloud) provides resizable virtual servers (instances) in the cloud. It is a Regional service - you launch instances in a specific Region and AZ.
  • You choose: instance type (CPU, memory, network), AMI (operating system + software), storage (EBS, instance store), network (VPC, subnet, security group), and IAM role.
  • EC2 has a per-Region limit on the number of running instances (default varies by instance type). Request increases via Service Quotas.
  • User Data: A script (bash or PowerShell) that runs once at instance first boot. Used for bootstrapping - installing software, pulling config, starting services. Runs as root. Not encrypted by default.
  • Instance Metadata (IMDS): Available at http://169.254.169.254/latest/meta-data/. Instances can query their own metadata. IMDSv2 is recommended over IMDSv1 for security. You can enforce IMDSv2-only.
  • MFA cannot be used with EC2 instance roles. MFA requires human interaction. aws:MultiFactorAuthPresent is always false for instance role credentials.

2. Instance Types

  • Instance type naming convention: m5.xlarge - m = family, 5 = generation, xlarge = size.
  • Key families for the exam:
    • General Purpose (M, T): Balanced compute, memory, networking. T-series are burstable and good for variable workloads. M-series for steady-state general workloads.
    • Compute Optimized (C): Best for batch processing, media transcoding, HPC, ML inference, gaming servers, scientific modeling.
    • Memory Optimized (R, X, z): Best for in-memory databases, real-time analytics, and large in-memory caches.
    • Storage Optimized (I, D, H): Best for data warehousing, distributed file systems, and high-frequency OLTP databases.
    • Accelerated Computing (P, G, Inf, Trn): GPUs or custom chips for ML training, ML inference, and graphics workloads.
  • T-series burstable deep dive: T3/T3a instances earn CPU credits at a baseline rate. If you consistently burst above the baseline, credits deplete and performance drops to baseline. Enable Unlimited mode to burst beyond credits.

3. AMI (Amazon Machine Image)

  • AMI is a template containing OS, application software, launch permissions, and EBS volume mappings. Required to launch an instance.
  • AMIs are Region-specific. To use an AMI in another Region, you must copy it to that Region.
  • AMI types: AWS-provided, AWS Marketplace, Community, and Custom.
  • Creating a custom AMI: Launch instance, configure it, then create an AMI. This creates EBS snapshots of all attached volumes.
  • AMIs can be shared with specific accounts, made public, or kept private. Encrypted AMIs shared cross-account require access to the KMS key.
  • Golden AMI pattern: Pre-bake a fully configured AMI with patches, software, and config for fast, consistent deployments.
  • AMI + EC2 Image Builder: Automates the creation, testing, and distribution of AMIs using pipelines.

4. Purchasing Options

  • On-Demand: Most flexible. Best for short-term and unpredictable workloads.
  • Reserved Instances (RI): One-year or three-year commitment for steady-state workloads. Up to 72 percent discount versus On-Demand.
  • Convertible Reserved Instances: More flexible than Standard RIs but with a smaller discount.
  • Savings Plans: Commit to a dollar amount per hour. Compute Savings Plans are the most flexible. EC2 Instance Savings Plans are more restrictive but can discount more.
  • Spot Instances: Up to 90 percent discount. AWS can reclaim them with two-minute notice. Best for fault-tolerant workloads.
  • Spot Fleets: A collection of Spot Instances and optionally On-Demand that tries to meet target capacity.
  • Spot Block: Deprecated but may appear on the exam.
  • Dedicated Host: Entire physical server dedicated to you. Required for server-bound software licenses.
  • Dedicated Instance: Hardware dedicated to your account, but without physical host control.
  • Capacity Reservations: Reserve On-Demand capacity in a specific AZ without billing discounts.

5. EC2 Placement Groups

  • Cluster: Instances packed close together in the same AZ. Lowest latency and highest throughput. Best for HPC and low-latency applications.
  • Spread: Each instance on different physical hardware. Maximum seven instances per AZ per group. Best for critical applications that need isolated failure domains.
  • Partition: Instances divided into logical partitions on separate racks. Best for large distributed workloads like Hadoop, HBase, Cassandra, and Kafka.

6. Elastic Network Interfaces (ENI)

  • ENI is a virtual network card attached to an instance. Each instance has a primary ENI that cannot be detached.
  • You can attach secondary ENIs for multi-homed instances, failover, and low-budget high availability solutions.
  • ENIs are AZ-specific - you cannot attach an ENI from one AZ to an instance in another AZ.
  • Each ENI has a primary private IPv4, optional secondary private IPv4s, Elastic IPs, IPv6 addresses, security groups, a MAC address, and a source or destination check flag.

7. Elastic IP

  • Static public IPv4 address. You own it until you release it.
  • You are charged if the Elastic IP is not associated with a running instance.
  • Limited to five per Region by default.
  • Can be moved between instances in the same Region for failover, though AWS recommends load balancers or DNS instead for high availability.

8. EC2 Storage - EBS (Elastic Block Store)

  • EBS volumes are network-attached block storage. They persist independently of the instance. They are AZ-specific.
  • EBS volume types:
    • gp3: Cost-effective default SSD choice with independently scalable IOPS and throughput.
    • gp2: Older general purpose SSD where IOPS scales with volume size.
    • io2 or io2 Block Express: Highest performance SSD for critical databases and sustained IOPS workloads.
    • io1: Older provisioned IOPS generation being replaced by io2.
    • st1: Throughput optimized HDD for big data and sequential workloads.
    • sc1: Cold HDD for infrequently accessed data at the lowest cost.
  • EBS Multi-Attach (io1/io2 only): Attach one EBS volume to up to 16 Nitro-based instances in the same AZ.
  • EBS Encryption: Uses KMS keys and encrypts both at rest and in transit between instance and volume.
  • Delete on Termination: Root volumes default to delete. Additional volumes default not to delete.

9. EBS Snapshots

  • Snapshots are point-in-time backups of EBS volumes stored in S3 and are incremental after the first snapshot.
  • Snapshots are Region-specific but can be copied cross-Region and cross-account.
  • You can create a volume from a snapshot in any AZ within the Region. This is how you move an EBS volume to another AZ.
  • EBS Snapshot Archive: Cheaper archive tier with retrieval taking 24 to 72 hours.
  • Recycle Bin for EBS Snapshots: Protects against accidental deletion with configurable retention.
  • Fast Snapshot Restore (FSR): Eliminates first-access latency for volumes created from snapshots.
  • Best practice: for strong data consistency, stop the instance or freeze the filesystem before snapshotting.

10. Instance Store (Ephemeral Storage)

  • Physically attached disk on the host machine with extremely high IOPS. Included in the instance cost.
  • Data is lost when: the instance is stopped, terminated, or the underlying hardware fails. Data survives a reboot.
  • Cannot be detached or reattached. Size and type are fixed by the instance type.
  • Best for buffer, cache, scratch data, and temporary content. Not for databases or persistent data.
  • Exam trap: highest possible IOPS means Instance Store. Data that must persist means EBS.

11. EFS (Elastic File System)

  • Managed NFS file system. Multi-AZ and can be mounted by hundreds of Linux instances across AZs simultaneously.
  • Use cases: Content management, web serving, shared home directories, and big data analytics requiring shared file storage.
  • Scales automatically as you add or remove files and can grow to petabytes.
  • Performance modes: General Purpose for low latency and Max I/O for higher throughput with slightly higher latency.
  • Throughput modes: Bursting and Provisioned (Elastic).
  • Storage Classes: Standard, Infrequent Access, One Zone, and Archive.
  • EFS vs EBS vs Instance Store: EFS is shared and multi-AZ, EBS is single-AZ block storage, Instance Store is ephemeral with highest IOPS.

12. EC2 Hibernate

  • When you hibernate an instance, RAM contents are saved to the root EBS volume and restored on restart.
  • Requirements: EBS root volume, encryption, and enough root volume space to hold the RAM dump. Supported on On-Demand, Reserved, and Spot Instances.
  • RAM size limit: up to 150 GB.
  • Maximum hibernation duration: 60 days.
  • Use cases: Long-running processing tasks, services with long initialization times, and preserving application state.
  • Exam pattern: resume an instance exactly where it left off or preserve RAM state means EC2 Hibernate.

13. EC2 Instance Lifecycle & States

  • States: pending to running to stopping and stopped, or shutting-down and terminated.
  • Stopped: EBS persists and there are no compute charges. You can change instance type and modify user data while stopped.
  • Terminated: Instance is deleted. Root EBS volume is deleted by default if Delete on Termination is enabled.
  • Stop Protection: Prevents accidental stop.
  • Termination Protection: Prevents accidental termination from console or API, but not every termination path.
  • Shutdown Behavior: Controls whether OS shutdown stops or terminates the instance.

14. Security Groups & Key Pairs

  • Security Groups: Stateful firewall at the ENI level with allow rules only. Changes take effect immediately.
  • Key Pairs: Used for Linux SSH access or Windows admin password decryption. If you lose the private key, you must create a new one and update the instance manually.
  • EC2 Instance Connect: Browser-based SSH using a one-time SSH key pushed to instance metadata.
  • Systems Manager Session Manager: Access instances without SSH keys or opening port 22. Preferred exam answer for secure, auditable access.

15. Auto Scaling Group (ASG)

  • Automatically adjusts the number of EC2 instances based on demand and replaces unhealthy instances.
  • Components:
    • Launch Template (preferred): Defines what to launch and supports versioning, mixed instances, and Spot plus On-Demand mix.
    • Launch Configuration (legacy): Older, less flexible option being phased out.
  • Scaling Policies: Target Tracking, Step Scaling, Simple Scaling, Scheduled Scaling, and Predictive Scaling.
  • Cooldown Period: Default 300 seconds to prevent rapid scaling oscillation.
  • Warm Pool: Pre-initialized instances for faster scale-out.
  • Instance Refresh: Gradual replacement of all instances after updates such as a new AMI.
  • Health Checks: EC2 or ELB. ELB is recommended when instances are behind a load balancer.
  • Termination Policy: Controls which instance is terminated during scale-in.
  • Lifecycle Hooks: Pause launch or termination to run custom actions.

16. Elastic Load Balancing (ELB)

  • Distributes traffic across multiple targets and is fully managed by AWS.
  • Types:
    • Application Load Balancer (ALB): Layer 7. Best for path-based and host-based routing in modern web applications.
    • Network Load Balancer (NLB): Layer 4. Best for extreme performance, static IPs, and non-HTTP protocols.
    • Gateway Load Balancer (GWLB): Layer 3. Best for routing traffic through third-party security appliances.
    • Classic Load Balancer (CLB): Legacy. Know it exists but do not choose it on the exam.
  • Cross-Zone Load Balancing: ALB enabled by default. NLB and GWLB disabled by default.
  • Connection Draining / Deregistration Delay: Allows in-flight requests to complete.
  • Sticky Sessions: Keeps the same client on the same target.
  • SSL/TLS Termination: Use ACM for certificates. ALB and NLB support SNI.

17. ALB Advanced Features

  • Target Groups: Logical groups of targets. ALB routes based on rules to target groups.
  • Health Checks: Per target group configuration with path, protocol, thresholds, and intervals.
  • Listener Rules: Conditions include path, host, method, query string, and source IP. Actions include forward, redirect, and fixed-response.
  • Authentication: ALB can authenticate users using Cognito User Pools or any OIDC-compliant IdP.
  • Lambda as Target: ALB can directly invoke Lambda functions.
  • Slow Start Mode: Gradually increases traffic to newly registered targets.
  • X-Forwarded-For Header: Preserves the client’s real IP address for the target.

18. ELB + ASG Integration

  • ASG automatically registers new instances with the target group and deregisters terminated ones.
  • Use ELB health checks in ASG when behind a load balancer so application-level failures trigger replacement.
  • Exam pattern: If instances are running but users see errors, switch ASG health checks from EC2 to ELB.

19. High Availability & Disaster Recovery Patterns

  • Multi-AZ deployment: Use ALB or NLB plus ASG across multiple AZs.
  • Multi-Region deployment: Use Route 53 with health checks and failover routing between Regions.
  • Elastic IP failover: Move an Elastic IP from a failed instance to a standby.
  • ENI failover: Move a secondary ENI and its private IP to a standby instance.

20. EC2 Monitoring

  • CloudWatch Basic Monitoring: Free metrics every five minutes.
  • CloudWatch Detailed Monitoring: Paid metrics every one minute.
  • CloudWatch does not collect by default: Memory utilization, disk space usage, and swap usage. Use the CloudWatch Unified Agent.
  • Status Checks: System Status Check for AWS infrastructure issues and Instance Status Check for guest OS issues.
  • EC2 Auto Recovery: Automatically recover an instance when a system status check fails.
  • CloudWatch Unified Agent: Collects both metrics and logs and can be centrally configured through SSM Parameter Store.

21. EC2 Nitro System & Performance

  • Nitro System: Next-generation virtualization platform with better performance, networking, and hardware-level security.
  • Enhanced Networking (SR-IOV): Higher bandwidth, higher PPS, and lower latency using ENA.
  • Elastic Fabric Adapter (EFA): For HPC and ML workloads requiring ultra-low latency inter-instance communication.
  • Exam performance hierarchy: Instance Store > io2 Block Express > io2 or io1 > gp3 > gp2 > st1 > sc1.

22. EC2 Cost Optimization Strategies

  • Right-sizing: Use AWS Compute Optimizer to recommend better instance types based on usage.
  • Spot Instances for fault-tolerant workloads: Use for batch processing, CI/CD runners, data analysis, and render farms.
  • Reserved Instances or Savings Plans for steady workloads: Best for databases, core app servers, and baseline capacity.
  • Scheduled Reserved Instances: For predictable recurring workloads that do not run 24/7.
  • Auto Scaling: Scale in during low demand to avoid paying for idle capacity.
  • Instance type with right purchasing option: Use Graviton instances for better price-performance when compatible.

AWS S3 - Complete SAA-C03 Cheat Sheet

A simple text reader version of the full S3 cheat sheet, preserving the original section structure and decision matrix.

1. S3 Fundamentals

  • S3 (Simple Storage Service) is object storage, not block storage or file storage. Buckets are created in a specific Region even though the service has a global console.
  • Object: A file plus metadata. Each object has a key, a value up to 5 TB, a version ID, metadata, and tags.
  • Bucket: A container for objects. Bucket names are globally unique across all AWS accounts and must follow naming constraints.
  • There is no limit on the number of objects in a bucket. Buckets per account default to 100 and can be increased.
  • S3 is designed for 11 nines of durability. Standard data is replicated across at least three AZs.
  • Consistency model: Strong read-after-write consistency for PUT and DELETE.

2. S3 Storage Classes

  • S3 Standard: Frequently accessed data with no retrieval fee.
  • S3 Intelligent-Tiering: Automatically moves objects between tiers based on access patterns for unpredictable workloads.
  • S3 Standard-IA: Lower storage cost with retrieval fee for infrequently accessed data needing millisecond retrieval.
  • S3 One Zone-IA: Cheaper than Standard-IA but stored in a single AZ.
  • S3 Glacier Instant Retrieval: Archive storage with millisecond retrieval.
  • S3 Glacier Flexible Retrieval: Archive storage with retrieval in minutes to hours.
  • S3 Glacier Deep Archive: Cheapest archive option with retrieval in 12 to 48 hours.
  • Key exam comparison: Unknown access patterns means Intelligent-Tiering. Cheapest long-term archive means Glacier Deep Archive.

3. S3 Lifecycle Rules

  • Lifecycle rules automate transitions between storage classes and expiration of objects.
  • Transition Actions: Move objects to cheaper storage classes after a number of days.
  • Expiration Actions: Delete objects, delete expired delete markers, or delete incomplete multipart uploads.
  • Rules can apply to entire buckets, prefixes, tags, or combinations.
  • Transition constraints: You can only transition downward in the storage hierarchy.
  • S3 Analytics: Recommends Standard to Standard-IA transitions based on access patterns.

4. S3 Versioning

  • Versioning keeps multiple versions of an object in the same bucket. Once enabled, it can only be suspended, not disabled.
  • Every overwrite or delete creates a new version. Old versions remain billable.
  • Deleting a versioned object: A delete request adds a delete marker. To permanently delete, delete the specific version ID.
  • MFA Delete: Requires MFA to permanently delete a version or change versioning state. Only root can enable it via CLI.
  • Versioning is required for S3 Replication.

5. S3 Replication

  • Cross-Region Replication (CRR): Replicates to a bucket in another Region for DR, compliance, or low-latency access.
  • Same-Region Replication (SRR): Replicates to another bucket in the same Region.
  • Requirements: Versioning on source and destination plus proper IAM permissions.
  • Only new objects replicate by default after replication is enabled. Existing objects need S3 Batch Replication.
  • Replication Time Control (RTC): SLA-backed replication within 15 minutes for extra cost.

6. S3 Security - Bucket Policies

  • Bucket Policy: Resource-based JSON policy controlling bucket access and conditions.
  • ACLs: Legacy access control. AWS recommends disabling them with Object Ownership set to bucket owner enforced.
  • Block Public Access: Account-level or bucket-level settings that override policies and ACLs to prevent public access.
  • Exam pattern: To ensure no bucket in an account can ever be public, enable Block Public Access at the account level.

7. S3 Security - Encryption

  • SSE-S3: AWS-managed keys, default on new objects, no extra configuration.
  • SSE-KMS: Uses KMS keys and allows auditing through CloudTrail, but can hit KMS API limits.
  • SSE-C: You provide the key with every request. AWS does not store it.
  • DSSE-KMS: Dual-layer encryption using KMS for highly regulated workloads.
  • Client-Side Encryption: Data is encrypted before upload and S3 stores ciphertext only.
  • Encryption in transit: Enforce HTTPS with a bucket policy condition on aws:SecureTransport.
  • Default encryption: Buckets can enforce a default encryption method.

8. S3 Security - Access Control Deep Dive

  • IAM Policy: Identity-based control for users, roles, or groups.
  • Bucket Policy: Resource-based control, required for cross-account access and condition enforcement.
  • Evaluation logic: IAM and bucket policies combine, unless either contains an explicit deny.
  • VPC Endpoint policy: Restricts which buckets or actions are allowed through a Gateway VPC Endpoint.
  • Access Points: Simplify access management for shared datasets with per-access-point policies.
  • Object Lambda Access Point: Transforms data on the fly using Lambda before returning it.
  • Pre-Signed URLs: Temporary URLs for time-limited access to upload or download a specific object.

9. S3 Performance Optimization

  • Baseline performance supports 3,500 write-type requests and 5,500 read-type requests per second per prefix.
  • Multipart Upload: Required for objects larger than 5 GB and recommended for objects larger than 100 MB.
  • S3 Transfer Acceleration: Uses CloudFront edge locations to speed up long-distance uploads.
  • S3 Byte-Range Fetches: Parallelize downloads or fetch only parts of large objects.
  • S3 Select / Glacier Select: Query subsets of data inside objects using SQL.
  • Prefix design: Spread reads and writes across multiple prefixes for parallelism.

10. S3 Event Notifications

  • S3 can trigger notifications when objects are created, deleted, or restored.
  • Destinations: SNS, SQS, Lambda, and EventBridge.
  • Exam pattern: Process images on upload means S3 event notification to Lambda. Complex routing usually means EventBridge.

11. S3 Object Lock & Glacier Vault Lock (WORM)

  • S3 Object Lock: Prevents objects from being deleted or overwritten for a retention period. Requires versioning.
  • Governance Mode: Most users cannot delete, but privileged users can bypass in emergencies.
  • Compliance Mode: Nobody can delete or shorten retention, not even root.
  • Legal Hold: Indefinite hold that must be explicitly removed.
  • Glacier Vault Lock: Immutable Vault Lock policy for Glacier vault compliance archives.

12. S3 Static Website Hosting

  • S3 can host static websites directly with a website endpoint URL.
  • You must enable static website hosting and specify an index document.
  • Objects must be publicly readable, which means allowing s3:GetObject and disabling Block Public Access for the site bucket.
  • S3 + CloudFront: Common pattern for HTTPS, custom domains, global caching, and private bucket access using OAC.
  • CORS: Required when a site on one origin needs resources from another origin.

13. S3 Access Logs & Monitoring

  • S3 Server Access Logging: Logs all requests to a bucket and writes them to another bucket in the same Region.
  • CloudTrail Data Events: Object-level API logging for GetObject, PutObject, and DeleteObject. Not enabled by default.
  • S3 Storage Lens: Organization-wide visibility into storage usage and activity trends.
  • S3 Inventory: Daily or weekly inventory reports listing objects and metadata for auditing and analysis.
  • Exam trap: Never set the logging target bucket equal to the source bucket.

14. S3 Batch Operations

  • Perform bulk operations on billions of objects with a single request.
  • Operations include copying objects, invoking Lambda, restoring from Glacier, replacing tags, changing storage class, and encrypting objects.
  • Uses S3 Inventory or a custom CSV as the source list.
  • Supports retries, progress tracking, notifications, and completion reports.

15. S3 with Other AWS Services - Common Architectures

  • CloudFront + S3: Content distribution with OAC to restrict direct S3 access.
  • S3 + Athena: Query data in S3 using SQL without loading it into a database.
  • S3 + Macie: Discover and classify sensitive data in S3.
  • S3 + EventBridge + Lambda: Event-driven processing pipeline.
  • S3 + Glacier + Lifecycle Rules: Automated archival pipeline.
  • S3 as a data lake: Central repository for structured, semi-structured, and unstructured data.

16. S3 Requester Pays

  • With Requester Pays, the requester pays request and data transfer costs while the owner still pays for storage.
  • The requester must be an authenticated AWS user.
  • Useful for sharing large datasets without paying the download bill yourself.

17. S3 Multipart Upload & Limits

  • Object size limits: Single PUT max 5 GB. Multipart upload max 5 TB. Each part 5 MB to 5 GB. Maximum 10,000 parts.
  • Multipart upload is recommended for objects larger than 100 MB and required above 5 GB.
  • Incomplete multipart uploads continue to consume storage until aborted or cleaned up by lifecycle rules.

18. S3 Presigned URLs vs CloudFront Signed URLs

  • S3 Presigned URL: Temporary access to a specific S3 object using IAM principal credentials.
  • CloudFront Signed URL: Temporary access to a specific file through CloudFront with CDN delivery and access control.
  • CloudFront Signed Cookies: Temporary access to multiple files via CloudFront.
  • Exam decision: Single object direct from S3 means presigned URL. Multiple CDN files means signed cookies.

19. S3 Cross-Account Access Patterns

  • Bucket Policy: Simplest cross-account method for S3 access.
  • Cross-Account IAM Role: Other account assumes a role with S3 permissions.
  • ACLs: Legacy and not recommended.
  • Access Points: Cleaner cross-account access management than editing one large bucket policy.
  • Exam preference: Bucket policy is usually the simplest and most common answer.

20. S3 Transfer & Migration

  • S3 Transfer Acceleration: Ongoing accelerated uploads over the internet using edge locations.
  • AWS DataSync: Automated online transfer between on-premises, other clouds, and AWS storage services.
  • AWS Snow Family: Offline transfer for large migrations, from Snowcone up to Snowmobile.
  • Rule of thumb: If network transfer would take more than a week, use Snow Family.
  • AWS Storage Gateway: Hybrid storage service connecting on-premises systems with S3 and related storage options.
